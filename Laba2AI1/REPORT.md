# Отчёт: реализация искусственного игрока с алгоритмом Minimax

## 1. Описание выбранной игры

Реализована консольная игра **«Зубы крокодила»** для двух участников: человека и ИИ. В начале доступно 7 зубов. Игроки ходят по очереди и могут нажать 1 или 2 зуба (если зубов осталось меньше, то не больше оставшегося количества). **Игрок, нажавший последний зуб, проигрывает.** Ничья правилами игры не предусмотрена.

Состояние представлено структурой `GameState` с полями `remainingTeeth` (оставшиеся зубы) и `aiTurn` (чей ход следующий). `getValidMoves()` возвращает допустимые ходы, `applyMove()` создаёт следующее состояние, `isTerminal()` проверяет окончание игры.

## 2. Принцип работы Minimax

ИИ строит дерево возможных ходов, рассматривая собственные ходы и ответы человека. Функция `minimax(state, depth, isMaximizing, nodes)` перебирает каждый допустимый ход рекурсивно:

- На ходе ИИ (`isMaximizing = true`) выбирает **максимальную** оценку среди продолжений.
- На ходе человека (`isMaximizing = false`) выбирает **минимальную** оценку, то есть учитывает наиболее невыгодный для ИИ ответ противника.
- В терминальной позиции возвращает точную оценку результата. Если глубина равна нулю до достижения конца, возвращает эвристическую оценку.

`chooseBestMove()` сравнивает оценки всех допустимых ходов ИИ и выбирает ход с наибольшим результатом. В консоль выводятся оценки и число рассмотренных позиций (посещённых узлов поиска).

## 3. Оценочная функция `evaluate(state)`

Оценка всегда вычисляется **с точки зрения ИИ**:

| Ситуация | Оценка |
|---|---:|
| Человек нажал последний зуб (победа ИИ) | `+100` |
| ИИ нажал последний зуб (поражение ИИ) | `-100` |
| Нет терминала, позиция выгодна ИИ | `+10` |
| Нет терминала, позиция невыгодна ИИ | `-10` |

По правилам игры проигрышной для **игрока, которому предстоит ходить**, является позиция, в которой количество оставшихся зубов даёт остаток **1 при делении на 3**, то есть `remainingTeeth % 3 == 1` (например, 1, 4, 7). Эвристика использует это свойство, учитывая, чей сейчас ход. Ничьи невозможны, поэтому оценка `0` для них не требуется.

В терминальном состоянии ход уже передан следующему участнику: `aiTurn == true` означает, что последним ходил человек и проиграл.

## 4. Пример выбора хода ИИ

Пусть первым ходил человек и нажал **1** зуб. Осталось **6** зубов, очередь ИИ:

- Если ИИ нажмёт **1**, останется **5** зубов — при безошибочной игре человек сможет выиграть (оценка `-100`).
- Если ИИ нажмёт **2**, останется **4** зуба — это проигрышная позиция для человека при оптимальной игре (оценка `+100`).

Поэтому Minimax выбирает **2 зуба**. Далее человек может нажать 1 или 2, а ИИ отвечает так, чтобы оставить **1 зуб** человеку. Человек вынужден нажать последний зуб и проиграть.

## 5. Ограничение глубины поиска

В программе задано `SEARCH_DEPTH_LIMIT = 7`. Ограничение позволяет контролировать число анализируемых уровней дерева и будет полезно при увеличении количества зубов или ветвления. После достижения лимита Minimax использует эвристическую оценку вместо полного просмотра продолжений.

**При текущих настройках (7 зубов, лимит 7) дерево просматривается до завершения партии**, поэтому результаты `+100` и `-100` точны, а эвристика для исходной игры фактически не нужна. Для демонстрации работы эвристики можно временно снизить `SEARCH_DEPTH_LIMIT`, например до `3`. Тогда решение станет зависеть от приблизительной оценки на границе поиска.

## 6. Вывод

Разработана консольная игра «человек против ИИ» с состоянием игры, генерацией и применением ходов, проверкой терминальных позиций, оценочной функцией и рекурсивным поиском Minimax. ИИ выбирает решения с учётом оптимального ответа противника. Игра не включает ничьи, поскольку они не допускаются правилами.
